# Claude 구현 작업지시서 — 해외 구매대행 v1

이 문서와 `purchasing-agent-plan.md`를 함께 읽는다. 상태: 전달 준비, Claude 실행 미확인.

## 역할과 범위

ChatGPT가 기획, Claude가 코드와 테스트, 사용자가 운영 승인을 담당한다.
요구사항: 해외 구매대행 / 타오바오 / 소형 생활·수납용품 / 주 고유 상품 100개 / 예상 공헌이익률 20% / 스마트스토어·당근·번개장터 / Windows 예약 실행.
최초 작업은 아래 1단계 구현이다. 실제 장바구니 변경·상품 게시·구매·결제·고객 연락을 이 지시서만으로 실행하지 않는다.

## 먼저 할 일

1. 작업 저장소에 있는 AGENTS.md, CLAUDE.md 및 적용되는 운영 정책을 확인한다. 허브 원장 작업 ID는 T-COMMERCE-001이다. AUTO-NAVER만 허용된 실행에서는 다른 저장소를 읽거나 수정하지 않는다. 허브 원장 갱신은 ChatGPT가 담당한다.
2. AUTO-NAVER 기존 수집·승인·네이버 연동·테스트·의존성 구조를 읽는다. 접근할 수 없으면 원인을 기록하고 구현 완료를 주장하지 않는다.
3. 기존 구조를 재사용할 수 있는지 근거를 남긴다. 새 저장소·전체 재작성·프레임워크 교체를 임의로 시작하지 않는다.
4. 클라우드 작업은 이미 격리돼 있으므로 기존 체크아웃을 사용하며 사용자가 요청하지 않은 Git worktree를 만들지 않는다. 코드 변경은 전용 기능 브랜치에서 수행한다.
5. 실제 고객 정보나 세션 없이 합성 데이터로 시작한다. 비밀 값은 읽거나 출력하거나 커밋하지 않는다.

## 1단계 납품물

- 상품/옵션 JSON 또는 CSV 가져오기와 입력 검증. 실제 타오바오 수집이 작동한다고 표시하지 않는다.
- 채널별·옵션별 Decimal 가격 엔진. 배송 포함/별도, 채널 요율, 고정 수수료, 충당금, 환율, 비용 근거 시각을 지원한다.
- 상품·옵션·견적·번역 초안·승인·실행 이력을 보존하는 저장 구조 및 필요한 마이그레이션.
- 로컬 검토 화면: 후보, 근거 부족, 가격 구성, 예상 마진, 원문/번역 비교, 채널 상태, 일괄 검토/제외.
- 승인된 버전에만 연결되는 모의 게시 어댑터. 실계정 게시와 확실히 구분한다.
- 텍스트·옵션표·이미지 목록·채널별 가격을 담은 초안 패키지 내보내기.
- Windows 설치/시작/중지/재시작/예약 등록 절차와 재현 가능한 테스트 명령.
- 결과 보고서에 작업 ID·근거·남은 제약·다음 행동을 기록하고 ChatGPT가 허브 원장을 갱신할 수 있도록 전달한다. 기능 브랜치와 Draft PR로 검토하며 자동 머지/배포하지 않는다.

## 1단계 필수 수용 테스트

1. C=30,000, 수수료 6%, 무료배송, 목표 20%이면 100원 올림 판매가 40,600원, 이익 8,164원, 이익률 약 20.1084%.
2. 별도 배송비가 총 수입·실제 배송비·수수료에 각각 올바르게 반영되고 두 번 더해지지 않는다.
3. 채널/옵션별 비용이 다르면 독립적인 판매가와 이익률을 생성한다. 할인 후 마진 미달도 탐지한다.
4. 무게/배송 요율/환율/수수료가 없거나 만료되면 0값으로 대체하거나 게시 가능한 가격으로 확정하지 않는다.
5. 분모 0 이하, 음수, 잘못된 통화, 비정상 수량 입력은 명시적인 검증 오류를 반환한다.
6. 원가·환율·옵션·이미지·번역·배송 조건 변경 또는 승인 만료 시 이전 승인을 사용할 수 없다.
7. 미승인 상품, 미검증 채널, 필수 판매 근거 누락, 마진 미달은 게시 요청을 생성하지 않는다.
8. 같은 주 또는 다음 주 재실행에도 같은 계정·상품·채널의 중복 게시가 발생하지 않는다.
9. 등록 후 응답 유실은 unknown으로 기록한다. 조회로 확인되지 않는 동안 무조건 다시 POST하지 않는다.
10. 100개 고유 상품·최대 300개 채널 작업의 모의 실행이 중간 재시작에도 결과를 보존한다. 실제 게시 성공으로 집계하지 않는다.
11. 100개 미만만 통과하면 실제 수와 제외 이유를 보고하며 허위 데이터로 보충하지 않는다.
12. 가져오기 자료의 스키마 버전·필수 필드·타입·중복 ID를 검증한다. 외부 텍스트/HTML을 실행하지 않는다.
13. 로컬 관리 화면의 인증·상태 변경 보호, 로그 비밀정보 누락, 모의 작업 중복/강제 종료 복구를 검증한다.
14. 동시에 두 작업자가 게시를 요청하거나 승인 직후 가격이 바뀌어도 버전 검사와 원자적 작업 점유로 중복/미승인 게시를 막는다.
15. 할인 후 결제액에 반영된 할인을 재차 차감하지 않는다. 원단위 수수료 처리 규칙을 명시하고 고정 기대값으로 검증한다.

## 후속 단계 수용 테스트 (1단계 완료로 간주하지 않음)

- 2단계: 30일 근거 부족과 누적 판매량을 월간 성장률로 표현하지 않는다. 번역에서 숫자/단위/옵션의 불일치를 검수 대상으로 표시한다.
- 3~4단계: 실제 로그인 만료, 허용된 장바구니 변경, 채널별 등록/조회, 요청 결과 불명확 상태를 검증한다. 운영 승인 전에는 모의 검증만 한다.
- 5단계: Windows 실제 PC에서 작업 스케줄러, 잠금/절전/미로그인, 재부팅 후 복구를 검증한다. Linux 테스트 결과로 대체하지 않는다.

## 후속 연동 때 확인할 사항

각 채널은 공식 근거 URL과 확인일, 계정 권한, 해외 구매대행 상품 허용 범위, API/브라우저 자동화 지원 상태를 기록한다.
지원되지 않는 기능은 blocked 또는 수동 내보내기로 표시한다. 임의 API·CAPTCHA 우회·접근 제한 회피로 채우지 않는다.
Windows에서 기존 Chrome을 제어할 수 있다고 가정하지 말고 전용 프로필의 수동 로그인부터 검증한다.
개발용 Claude Pro 구독을 무인 번역 API라고 취급하지 않는다. 유료 API·추가 과금으로 자동 전환하지 않는다.
결제·주문·실제 게시·계정 권한 변경에는 해당 작업에 대한 별도 운영 승인이 필요하다.

## 결과 보고 형식

검증 대상 커밋 SHA, 변경 파일, 실제 테스트 명령과 종료 코드, 통과/실패/미실행 개수, 모의/실계정 여부, Windows 검증 여부, 알려진 제한, 다음 행동, Draft PR 링크를 보고한다.
검증되지 않은 API 연동이나 새 환경 복원을 완료했다고 쓰지 않는다. 1단계 완성은 전체 3채널 자동 판매 완성을 뜻하지 않는다.
